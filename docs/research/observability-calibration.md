## 1. 样本范围与口径

### 1.1 观测 step 的可用起点

CI 观测 step `Report streaming budget instruments (observation only, non-gating)` 由 `008a9670a`（2026-11-06 07:48Z）引入。实测 11-02 的 push run `41493296103` 日志中 `peakHeldBytes` / `initScanUs` 均 **0 匹配**；`008a9670a` 之后的所有候选 run 均为 24 行 `MESSAGE`。故定标窗口从 11-06 09:12Z 起算，更早的 run 不纳入。

### 1.2 「连续 ≥10 次」的口径说明

窗口内共有 **13 次成功的、push 到 master 的 `sdk-coverage` run**，全部纳入。期间另有 2 次失败 push run（`42233577631` / `42242478290`）与 1 次 attempt 1 失败（`42442116861`，已按既有约定用 `gh run rerun --failed` 取证、attempt 2 成功）。

规格 §3.2 的「连续不少于 10 次成功的 run」按**连续时间窗内的全部成功样本**解释，不因偶发失败丢弃整段：Linux coverage 存在已登记的低概率单目标 flake，若要求「中间一次失败都不能有」，定标将永远凑不满，且与「用 rerun 取证、不放宽判据」的既有处置冲突。如实登记：最长**无失败间隔**的连续成功段只有 6 次（11-06 上午）与 5 次（11-07～11-08），样本总量满足 ≥10，但「无失败连续段」不满 10。

排除项：PR run（`42442016087` 等，与 push run 同 headSha 的重复样本）、`sdk-windows`（无等价观测 step）、step 引入前的 run。

### 1.3 取数口径坑：源码行号会漂移

11-06 的 8 个 run 里观测点落在 `test_streaming_budget.cpp:265` / `:620` / `:1370`；`af6373b2f`（11-07）之后变成 `:294` / `:649` / `:1402`。**字段文本完全一致，只有源码行号变了**。取数必须按字段语义匹配，不能硬编码行号，否则会凭空丢掉 8 个样本、把 13 次分布误算成 5 次。

## 4. µs 时间值的离群：`boundaryMicros`

`boundaryMicros` 是现场重算包边界的墙钟测量，13 run × 6 格式 = 78 个样本。

| 格式 | min / 中位数 / max (µs) | 极差 | 不同取值数 |
|---|---|---|---|
| mkv | 82 / 204 / 337 | 4.11× | 13 |
| music-alac.m4a | 67 / 271 / 366 | 5.46× | 13 |
| music-ape.ape | 25 / 68 / 178 | 7.12× | 13 |
| 十七岁-陶喆.96.wma | 588 / 6700 / 7887 | 13.41× | 13 |
| 摇滚乐_Freesound.m4a | 103 / 600 / 2084 | 20.23× | 13 |
| 萨克斯机.asf | 127 / 313 / 478 | 3.76× | 13 |
| **全部 78 个样本** | **25 / 292 / 7887** | **315.48×** | **77** |

**离群归因**：`boundaryMicros` 全距 25–7887 µs、极差 315×、78 个样本里 77 个不同值；wma 单格式就跨 588–7887 µs。它测的是「逐包边界重算」的一次墙钟耗时，受 runner 负载、页缓存、CPU 调度与素材包数共同影响，不是被测对象的稳定属性。**结论：µs 时间值不宜直接定标为门禁阈值**；若将来要立判据，须先按格式分组、剥离冷/热 runner 与离群，再按 §3.2 第 4 步单开票。这与规格 §3.2「结构与时间值要分开看」以及 §3.2 第 3 步「逐个解释离群」一致。

## 5. 冷 / 热 runner 覆盖

13 次 run 耗时 11.3–29.1 min，中位数 17.2 min。该窗口内 `sdk-coverage` **没有** `sdk-windows` 那种 5 min 级热跑；按 <14 min 记「偏热」、≥14 min 记「偏冷」近似，偏热 4 次、偏冷 9 次，两种状态都覆盖。结构值在两组中均恒定，时间值未见与耗时单调相关（例如最快的 `4aad2caca` 11.3 min 的 A `initScanUs=24`，最慢的 `393a32131` 29.1 min 反而 `26`）。

这是**耗时近似**，不是从 runner 缓存日志直接判定；如需精确冷热标记，属后续 effort，本文不伪造。
