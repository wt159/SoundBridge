# 0012 app 层界面契约：行为优先、锚点为判据、暂不引入自动化

- 状态：已接受
- 日期：2026-11-21
- 来源：[地图：app 层 UI 契约](https://github.com/wt159/SoundBridge/issues/216)、[契约边界、真相源与判据锚点](https://github.com/wt159/SoundBridge/issues/217)、[三态与时间显示的可判定映射](https://github.com/wt159/SoundBridge/issues/218)、[列表条目与点选语义](https://github.com/wt159/SoundBridge/issues/219)、[传输控制与播放模式的可见语义](https://github.com/wt159/SoundBridge/issues/220)、[错误呈现与持久化键表](https://github.com/wt159/SoundBridge/issues/221)、[视觉不可回归约束与占位控件](https://github.com/wt159/SoundBridge/issues/222)、[判据形态与手工冒烟清单](https://github.com/wt159/SoundBridge/issues/223)、[app 层自动化 UI 测试的可行性](https://github.com/wt159/SoundBridge/issues/224)。规格落点 [`doc/app-ui-spec.md`](../../doc/app-ui-spec.md)。

## 背景

`app/` 至今零规格。`doc/player-state-contract.md:15` 明确裁定「只含 sdk 公开契约；`app/` 只作事实来源与验收场景；不重设计 UI、不重构 `PlayerViewState`」。结果是界面的可见行为没有判定标准：三个按钮是空槽（收藏还会把图标切换成「已收藏」并永久悬挂）、三段样式表选择器指向不存在的对象名、切歌允许闪 `IDLE`、停止态保留曲名、错误文案保留到换曲——这些要么是事实，要么是偶然，读者无法区分。

同时，app 层的改动缺少回归基线：`scripts/ui.py` 能截图与点击，但没有「应该看到什么」的文本；SDK 侧判据再密，也覆盖不到按钮勾选、列表标记、弹窗字段。

## 决策

**为 `app/` 单独建一份行为契约规格，以 `objectName` 作为判据锚点，视觉只锁不可回归项；首版不引入自动化 UI 测试。**

- **规格独立成文**：新建 `doc/app-ui-spec.md`；SDK 规格既有行一字不动，只在 `player-state-contract.md` §1 加一行纯新增指针。理由：那份规格的单一职责是公开契约，把 UI 塞进去会让「SDK 承诺」与「界面习惯」混在同一份文件里。
- **行为优先**：锁可见结果（文案、勾选、列表标记、滑块位置）、锚点、持久化键名、错误文案分档；不锁 `PlayerViewState` 字段结构、不锁像素与色值、不锁控件实现。视觉只保留八条不可回归约束（双栏、最小尺寸、深色可读、三态可区分、图标完整、选择器合法、资源存在、遮罩不拦截鼠标）。
- **三层真相源**：播放器事实（SDK 回调）→ UI 缓存（`PlayerViewState`）→ 控件外观（`renderPlayerViewState`）。只允许单向：控件点击表达意图，结果以回调为准；界面不得反向写播放状态。
- **锚点即契约**：`objectName` 被规格锁定，改名视为破坏契约；qss 选择器必须指向锚点。现状三段不匹配（`#listWidget` / `#listMask` / `#durationSlider`）与两处单冒号子控件、一处拼写错误，按「以锚点为准改选择器/删死规则」修正，不反向改锚点。
- **占位控件显式化**：收藏/菜单/音量三个空槽一律 `enabled = false` + tooltip `Not implemented`；收藏去掉 `checkable`，避免图标悬挂成「已开启」。功能实现属界外，占位状态必须可判定。
- **判据分两类**：A 类可脚本核对（锚点集合、选择器、资源、常量、键名），B 类手工冒烟（12 步，含错误两态与持久化）。首版两者都不新增 ctest 目标。
- **暂不引入自动化 UI 测试**：QtTest + offscreen 本机可用（4 例 / 72 ms，见 [`docs/research/app-ui-test-feasibility.md`](../research/app-ui-test-feasibility.md)），但 `MainWindow` 没有状态注入缝，拆库/加渲染入口是一次 app 层 API 改动；新增测试目标还违反「保持 14 个 ctest 目标」的既有纪律。毕业条件写进规格 §9.5。

## 考虑过的替代方案

**(a) 把 UI 内容并入 `doc/player-state-contract.md`。** 少一份文件，读者只查一处。否决：该规格开篇即裁定「不含 UI」，改它会稀释单一职责；UI 契约的读者（改界面的人）与 SDK 契约的读者（接 SDK 的人）不是同一批。

**(b) 写像素级视觉规范（配色、字号、间距）。** 判据最硬。否决：仓库没有设计源，现有配色与图标是外部素材的遗留；像素规范会立刻与「不重设计 UI」的前提冲突，且截图比对在没有基线图的情况下仍靠人眼。

**(c) 首版直接引入 QtTest + offscreen 自动化。** 能自动判状态映射。否决（推迟）：框架可用不是瓶颈——瓶颈是 `MainWindow` 私有持有 `PlayerController`、控制器私有持有 `Player`，没有「给定 `PlayerViewState` 渲染」的入口；为测试先改 app 公开面，成本高于规格本身。且新增目标会打破 14 目标纪律，需要单独一次例外决策。

**(d) 直接移除三个空壳按钮。** 界面更诚实。否决：移除是产品决策，不是契约决策；保留并禁用既能让用户看见「将来会有」，也能让规格用一条判据锁住「不得假可用」。移除将来仍可做，只需先改规格。

**(e) 用 `PlayerViewState` 的字段集合作为契约。** 简单，可直接对着头文件核对。否决：字段是实现缓存，不是用户可见结果；锁定字段会把「换一种渲染方式」判成破坏契约，与「不重构 `PlayerViewState`」的既有裁定也冲突。

## 后果

- app 层首次有可判定的行为基线：12 步冒烟 + 6 条 A 类核对覆盖三态、列表、控制、错误、持久化、视觉与占位控件。
- 规格登记了三处现状偏差（4 个文本锚点待补、qss 死规则、占位控件可点），由**图外执行票**修正；规格本身不假装这些已满足。
- 停止态保留曲名与时长、错误文案保留到换曲、切歌允许闪 `IDLE`——三条都是**有意裁定**，不是遗漏；将来要改，先改规格。
- 自动化仍为零。引入的前置条件固定为三条（注入缝、CI QtTest 实测、目标预算例外），避免下一轮把「加个 UI 测试」当成顺手事。
- 界面文案锁定为英文；本地化（`tr()` 与语言资源）留在界外，将来是一次独立 effort。
- 最小尺寸 `960×540` 的「无裁切」未能成立（2026-11-21 实测：960×540 / 960×600 / 1000×700 均有裁切，1200×720 才完整）。规格已把 `UI-V2` 的通过条件收窄为默认尺寸，布局重排登记为缺口（[#228](https://github.com/wt159/SoundBridge/issues/228)）；本 ADR 不把该约束记为已满足。
- **补记（2026-11-21，收口后审计）**：上一条的「`1200×720` 才完整」是过强表述。补测客户端 `1100×720`（DPI 96，`GetClientRect` 复核）完整无裁切；已证裁切的三档仍为 `960×540` / `960×600` / `1000×700`，分界在 `1000×700` 与 `1100×720` 之间，精确定位归 [#228](https://github.com/wt159/SoundBridge/issues/228)。`UI-V2` 的通过条件（默认尺寸无裁切）不受影响。
- **补记（2026-11-21，[#228](https://github.com/wt159/SoundBridge/issues/228) 落地）**：上两条的缺口已关闭（PR [#232](https://github.com/wt159/SoundBridge/pull/232)，merge `50a0154f6`）。重排布局后 `960×540` 恢复为可兑现承诺：`960×540` / `960×600` / `1000×700` / `1100×720` / `1200×720` 五档实测无裁切、无重叠，`960×540` 下列表出现滚动条。`UI-V2` 的通过条件随之恢复为规格原文口径（`doc/app-ui-spec.md` §7 更正三）；「本 ADR 不把该约束记为已满足」仅作缺口期时点结论。
