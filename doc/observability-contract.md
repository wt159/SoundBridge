## 2. 术语与对象分类

「观测」在本规格里指三类互不混用的对象：

| 词 | 定义 | 不用来指 |
|---|---|---|
| **观测仪表** | 测试进程内由 `StreamingBudget` suite 经 `MESSAGE(...)` 输出的字段：`peakHeldBytes` / `silenceFills` / `startToFirstPcmUs` / `initScanUs`，及 `boundaryMicros` / `packets` / `packetsPulled` 等辅助字段 | 生产链日志里的量、任何判定结果 |
| **独立指标** | 生产链经 `Metrics::RecordTiming` 记录的量（`open_file_ms` / `track_switch_ms`），或口径已定义、取数点尚待落地的量（端到端 drift） | §5 的四条判据、测试仪表字段 |
| **契约漂移** | 公开 API 的签名 / 取值集合 / 事件序列相对 `doc/player-state-contract.md` 的可观察偏离，跨版本或跨运行 | 内部状态写入时机、ring 水位、WorkQueue 优先级等实现细节；单次偶发测试失败 |

「判据 / 观测 / 门禁」三者正交，不按同一维度切分：

- **判据** = 可红可绿的断言：§5 四条（常驻上界 / 并行 / 首播延迟 / 稳态欠流）、seek 精度、覆盖度 15 行、BadInput 55 例、播放器契约四条既有断言。
- **观测** = 只记录数值与事实、不参与红绿。
- **门禁** = 能让 CI 失败的检查。判据必然构成门禁的一部分；观测可以是非门禁，但不能因此说「观测没用」。

**播放时钟与源时钟**：源时钟 `S` 是当前已交付 PCM 对应的源时间轴位置（由包时间轴 / 标称时长给出）；播放时钟 `P` 是消费端累计 PCM 换算的 `positionMs = (segmentBaseBytes + m_readPos) / bytesPerMs`（沿用 #49 定义）。两者都不等于墙钟，也不等于「已听到的声音」——取的是**已消费**，ring 深度与 SDL 缓冲的恒定差额归偏置 `D₀`，不进 drift。

`GLOSSARY.md` 新增「观测与判定」章节收四个词条：观测仪表、独立指标、契约漂移、播放时钟与源时钟。「非门禁」是 CI 措辞而非领域概念，只在本规格定义。

|---|---|---|---|

### 3.1 非门禁的标准措辞（硬性）

每个 L1 / L2 / L3 项在规格、CI step 注释与文档里必须带这句，不得省略或改写：

> 本节数值只作观测记录，**不作为失败门禁**；记录失败（素材缺失 / 命令异常 / 无输出）不得让 CI 失败，也不得被解读为判据通过。

这句约束的是**失败语义**，不是「数值可以不看」。`continue-on-error: true` 与命令末尾 `|| true` **双保险都保留**：前者管 GitHub 步骤级失败，后者管 shell 命令级失败（`grep` 无匹配返回 1），覆盖的不是同一个失败面，去掉任一都会让观测 step 在某些失败形态下把 CI 染红。

### 3.2 定标 → 立判据的升级流程

地图已定「不为缺基线的指标拍数值阈值」。把这句写成可执行步骤：

1. **取数**：从连续不少于 10 次成功的、push 到 master 的 `sdk-coverage` run 里取 L1 / L2 数值，覆盖冷 / 热 runner 状态。这是**定标样本量，不是判据阈值**，不受「判据不新造」约束。
2. **归档**：按格式分组写入 `docs/research/` 下的事实基线，附 run id 与日志行号。
3. **看分布**：记 min / max / 中位数，逐个解释离群（冷启动、素材差异、runner 负载）。结构与时间值要分开看——实测结构值稳定（`peakHeldBytes 4608` 两轮一致），而 µs 时间值跨运行波动明显（`boundaryMicros 6541` vs `417`）。
4. **单开票拍板**：阈值、量纲与失败语义必须在一张独立 issue 里提出并留依据，不在规格里偷渡数字。
5. **生效前禁止**：阈值被拍板前，不得写入任何断言、不得注册 `add_test` 分组、不得把观测 step 改成门禁。

### 3.3 `TIMEOUT` 与 CI 分档

维持不动，归界外。#68 §12.4 第 4 条把「`sdk_unit_tests` 约 191 s 命中 `TIMEOUT 180`、是否调整交用户决策」留下，事实基线已推翻其前提：该目标现已拆分，CI 实测 14 个 `sdk_*` 目标全绿、总测试时间 67–97 s，`TIMEOUT` 未命中。本图按批量授权裁「不动」，不拆快集 / 全量集、不新增耗时 gate、不改覆盖度矩阵报告步骤。

### 3.4 稳态欠流判据的触发条件清单

`doc/streaming-playback-spec.md` §12.3 的假定今天仍成立（消费端不按实时墙钟节流；`shouldFillSilence()` 不读 ring 空条件、`got == 0` 不计数，判据实为「稳态窗口内静音填充为零」而非「无欠流」）。本图**不重开该判据**，但要求实现 effort 在下列任一条件出现时回来显式重审：

1. 消费模型改为水位驱动；
2. 出现真实解码慢于消费的用例；
3. `silenceFills` 的计数语义或豁免窗口发生变化。

### 3.5 数值阈值的最终裁决（2026-11-08，[#104](https://github.com/wt159/SoundBridge/issues/104)）

§3.2 第 4 步的单开票拍板由 #104 承接，按用户 2026-11-08 的一次性批量授权（「需要我拍板的问题都选择你的推荐」，见 #94 Notes）逐项裁决。**五项结论全部落在「维持只记录、不设任何数值阈值」**——这不是推迟决策，而是 13 run 实测数据支持的确定性结论：有样本的两类证明不适合设门禁，无样本的两类被硬约束禁止拍板，结构值已有 L0 判据覆盖。

| 量 | 裁决 | 依据 |
|---|---|---|
| drift `ρ` / `R` | **维持只记录，`R` 不拍** | O1 最小取数点未落地，无 `S(t)` / `P(t)` 实测序列，§3.2 第 1 步的取数前提根本不成立；任何数值都是凭空拍板 |
| `initScanUs` / `startToFirstPcmUs` | **维持只记录，不设上界** | 13 run 波动 1.5–1.9× 且取值互不相同，冷 / 热 runner 混杂（11.3–29.1 min）；设上界会把「runner 慢」误判为「产品回归」，与已登记的 Linux coverage 偶发 flake 同源 |
| `boundaryMicros` | **永久只记录** | 78 样本 25–7887 µs、极差 315×、77/78 互异；它测的是逐包边界重算的一次墙钟耗时，受 runner 负载 / 页缓存 / CPU 调度 / 素材包数共同影响，不是被测对象的稳定属性。任何上界要么宽松到无意义、要么必然 flaky |
| `peakHeldBytes` / `packets` / `delivered` / `upper` | **不需要新阈值** | 13 run 完全恒定（`distinct=1`），由素材与包契约决定；§6 的跨格式峰值差判据已通过、#48 常驻上界以单素材实测为准。再设上界是重复计量，还会制造第二个真相源 |
| `open_file_ms` / `track_switch_ms` | **维持只记录，禁止拍板；先做 O2** | CI 0 匹配、无样本；且 §5 明写 `initScanUs`(µs) 与 `open_file_ms`(ms) 不是同一量的两次测量、禁止跨源比较，不能拿 µs 基线给 ms 指标定标 |

**第 5 步的状态**：本次未拍板任何阈值，故「生效前禁止」由暂时生效转为**永久生效**——不得写入断言、不得注册 `add_test` 分组、不得把观测 step 改成门禁。§3.1 的非门禁标准措辞、`continue-on-error: true` + `|| true` 双保险、14 个 `sdk_*` 目标与全部既有判据数值一字不动。

**反悔通道**：若将来 O1 / O2 落地并确实要设阈值，**另开一张新票**（不重开 #104）重走 §3.2 五步：新证据需要新的定标样本与独立拍板，#104 的结论只覆盖「当前无样本 / 样本不适配」这一状态。新票在阈值被拍板前同样受第 5 步约束。

**授权说明**：#104 开票时打的是 `ready-for-human`，按「数值阈值须由人确认」的保守理解留给人。用户此前已明确给出「需要我拍板的问题都选择你的推荐」的批量授权（11-08 第三次写入 #94 Notes），且本次结论是**不新增任何门禁**的保守方向、零代码 / 零 CI / 零判据改动，故按该授权收口。若用户希望改为设具体数值，另开新票即可，不与本节冲突。

## 4. 端到端 drift 的定义、判定式与定标

### 4.1 取数点与量纲

- `S(t)`：源时钟，当前已交付 PCM 对应的源时间轴位置，**ms**。
- `P(t)`：播放时钟，消费端累计 PCM 换算的 `positionMs`，**ms**。
- `W(t)`：墙钟，仅用于标记采样时刻，**不进偏差式**（§3.4 的假定）。
- 偏置 `D(t) = P(t) − S(t)`；恒定部分 `D₀` 由 ring 深度与设备缓冲造成，**不是 drift**。drift 只量 `D` 随播放推进的变化量。

量纲用毫秒记录 `D`，判定用**相对漂移率** `ρ = ΔD / ΔP`（无量纲，可以 ppm 记）。理由：长时播放下绝对偏差会随时长线性放大，给绝对值设上界等于给「播多久」设上界，没有意义。

### 4.2 判定式（阈值待定标，本规格不拍）

```
ΔD = | D(t₂) − D(t₁) |
ρ  = ΔD / ( P(t₂) − P(t₁) )
判据形状：ρ ≤ R        （R 留空，按 §3.2 流程定标后单开票拍板）
```

采样在**稳态窗口**（首帧后 → EOS 前，排除启动 / seek / 切歌，沿用 §5 欠流窗口定义）按固定播放进度间隔取点（每 10% 标称时长一点，至少 5 点），不按墙钟采样。

**不复用 `max(1%,150ms)`**：那个是单次 seek 的定位误差容差，量的是「一次定位偏了多少」，绝对项与相对项混用且以标称值为基准；drift 量的是两条时钟随播放推进的**相对发散率**，量纲与统计对象都不同。复用会制造「每小时漂 1% 也算合格」这种规格从未承诺过的结论。这是「判据不新造」要求的显式理由：不新增数值，也不假借既有数值。

### 4.3 与既有判据的边界

首播延迟 `startToFirstPcmUs`、稳态欠流 `silenceFills == 0`、seek 精度三者都不量累计偏差。drift 若将来立判据，进**独立观测集**（L2 → L0 升级），不并入 §5 判据集，也不改 §5 任何一个数字。

### 4.4 最小取数点（图外 O1）

现状 `StreamMetrics` 无 drift 仪表。实现 effort 需要的最小改动是：在消费端提供 `S(t)` 与 `P(t)` 的**同一时刻同步快照**，禁止两值异步各取一次（会凭空造出抖动）。不新增同步解码入口、不改 `positionMs` 归消费端的归属、不改 10 ms push 节奏。

**2026-11-08 O1 落地（[#105](https://github.com/wt159/SoundBridge/issues/105)）**：`AudioStreamDecoder` 新增只读 `clockSnapshot()`（单次调用同返 `sourceMs` / `playMs`）与解码线程写的原子 `m_sourceClockMs`；`sourceMs` 复用 EOS 汇总 `measuredMs` 的公式，`playMs` 直接取 `positionMs()`。判据套件的稳态消费循环按 10% 标称时长只记录快照序列。未碰 `MusicPlayer.cpp` / `StreamMetrics.h` / CI / 任何既有 `MESSAGE` 与断言。

**口径限制（重要）**：`sourceMs` 是解码侧**产出**的源时间轴位置，与「已交付 PCM」差一个 ring 深度造成的恒定偏置 `D₀`（§4.1 明确不计入 `ΔD`）；且源钟按源采样率整数除法换算、播放钟按设备 PCM 字节 / `bytesPerMs` 换算，两者存在系统性比例差（长素材上 `D` 随进度缓慢变化）。因此本快照只能用于**同一实现内的纵向比较**，不得把绝对 `D` 当作产品 drift、不得跨源比较、不得据此拍 `R`；[#104](https://github.com/wt159/SoundBridge/issues/104)「不设任何数值阈值」的裁决不变。

### 4.5 定标流程

按 §3.2 五步；素材只用现有 15 行里时长最长的若干首，不合成长音频；冷 / 热 runner 各取一组；`ρ` 的分布稳定之前不谈 `R`。

## 5. 启动开销与切换开销的口径

| 量 | 单位 | 取数点 / 落点 | 判不判 | CI 可见性 |
|---|---|---|---|---|
| `initScanUs` | µs | init 期只读扫描，`StreamMetrics.h`，`StreamingBudget` 的 `MESSAGE` | 只记录 | 有数值（L1） |
| `open_file_ms` | ms | 生产链 `sdk/MusicPlayList.cpp:288-290` → `sdk/Metrics.cpp:46-49` | 只记录 | **不可见**（L2） |
| `track_switch_ms` | ms | `sdk/MusicPlayList.cpp:431`，起止沿用 #51：新任务 `start()` 之前销毁旧任务（stop+join 旧线程、旧 ring 引用计数归零、建新 ring / decoder） | 只记录 | **不可见**（L2） |

- `initScanUs` 与 `open_file_ms` **不是同一个量的两次测量**：前者测扫描 / 建索引，后者测「打开文件到可用」的更宽路径。规格禁止跨源相减、比较或互相换算；各自只能纵向跟自己的历史比。记录时保留原单位，比较前显式注明单位。
- 维持「只记录、不设阈值」并写入规格条款（含 §3.1 非门禁措辞）。理由是硬事实：两个生产链指标在 CI 里 0 匹配、连定标样本都没有，此时设阈值等于凭空拍板。
- 区分两种状态：`initScanUs` 属「已可见但不定标」；`open_file_ms` / `track_switch_ms` 属「代码已记录但 CI 不可见」。让后者在 CI 可见是图外 O2，且**不得为可见性去跑播放器生产链、不得新增耗时 gate**。
- 与 §5 判据不重叠：首播从 `AudioStreamDecoder::start()` 起算到设备首次 `write()`，**不含** init 只读扫描；切歌窗口也不进首播判据。将来若给这两项设阈值，须先证明不与「首播长短差 ≤150ms」重复计量。

## 6. 跨素材峰值差判据的状态（含一处事实更正）

### 6.1 更正

`doc/streaming-playback-spec.md` §12.4 第 3 条写「跨素材峰值差判据（`|peak_long − peak_short| ≤ P`）因素材矩阵缺口（ogg / wma 各仅 1 首、无同格式长短配对）不可验，#67 已如实标注」，**与事实冲突**：

- §5 原文要求的是「15 行**任意**长短素材对 `|peak_long − peak_short| ≤ P`」，从不要求同格式；#67 票面验收项明写「长短配对（3.7 s ogg ↔ 259 s wma）峰值差 ≤ P」，其 resolution comment 明写「StreamingBudget 四条判据全绿」。
- 事实基线下两个成功 CI run 都有 `peakHeldBytes` 数值（两轮均出现 `4608` 等），判据实跑过。

### 6.2 裁决

- 峰值差判据状态 = **已通过（按 §5 的跨格式长短配对）**，归入 L0，不是「不可验」、不是「未设立」。
- `P`（15 行实测最大包字节数 ×2）、15 行矩阵、判据表达式**一字不动**；**不降级为「只记录」** —— 把已有的可红可绿判据改成观测，等于改判据状态，违反「不改既有判据」。
- 「无同格式长短配对」只是**格式内交叉校验**没做，是增强项而不是判据成立的前置条件。事实基线显示 `.aac`（10 / 221 s）与 `.m4a`（69.9 / 12 s）其实已有同格式长短对，可做有限交叉校验；ogg / wma 各 1 首仍缺。
- 格式内交叉校验登记为 **L3 待验（非门禁）**：验证步骤归图外 O3，不补素材、不改 `P`、不重开 #48 常驻上界判据。上界仍以单素材实测为准，峰值差是交叉校验，两者不互相连累。
- 与 §4 drift 共享的长短配对依赖合并进 O3 一条，不另立清单项。

## 7. 播放器公开契约漂移的长期观测

### 7.1 观测对象与漂移定义

**契约面（必须观测）**：`PlayerState` 三态取值集合与迁移、六个回调及其顺序（曲目三连 `track → duration → position`、错误统一 `error → state`）、七个控制入口的 `void` 签名、`ErrorCode × ErrorAction` 表、`duration() == 0` 的空操作、「有码不承诺上报」三码清单。

**不观测**：内部 `MusicPlayerState` 写入时机、ring 水位、WorkQueue 优先级等实现细节。

漂移只指两类：① 跨版本：公开契约相对本规格 / `doc/player-state-contract.md` 的可观察偏离；② 跨运行：同一版本两次运行的事件序列契约不一致。文档措辞差异属文档维护，单次偶发失败属回归缺陷（由既有判据管），都不是漂移。

### 7.2 记录面：不新增任何东西

`sdk/test/mocks/PlayerMocks.hpp` 的 `event_sequence` / `position_values` 是**测试内记录器**，不跨运行留存；事实基线确认没有跨版本 / 跨运行的漂移记录面。**本图决定不补这个面**：不加 CI step、不加日志摘要、不新增耗时 gate、不加第二个真相源。

理由是契约面已有可红可绿判据在 14 个 ctest 目标里长期跑着（三连、幂等、position 单调、状态序列无相邻重复、`ErrorAction` 表）。**长期观测 = 规格 + ADR 的版本化记录 + 既有判据**：每次公开契约变更必须同步更新 `doc/player-state-contract.md`（§10）、`GLOSSARY.md` 词条与（必要时）`docs/adr/0004`，并在 PR 里引用；这就是「口径」，不需要新仪表。

### 7.3 非门禁措辞与既有判据并存（关键）

> 本节的**观测记录**不作为失败门禁；但契约本身仍由既有可红可绿判据门禁覆盖，二者不互替，也不得据此解读为「契约可以不测」。

这句与 §3.1 的标准措辞并列写进规格，专门防「只记录不设门槛」被读成「撤销测试」。

### 7.4 ADR 与判据缺口

**不开 `docs/adr/0005`**。三条判据逐条不成立：不改公开 API、不改变状态集合，没有难反悔的架构决策；「只记录 + 非门禁」是 #68 先例的直接沿用，无背景也不会惊讶；唯一的真实权衡「不为缺基线指标拍阈值」是地图前提，不是新架构决策。与 `docs/adr/0004-player-state-three-values.md` 是引用关系，不新增 ADR。

§10.4 登记的 **C1 error→state 顺序 / C5 设备错误不跳轨缺端到端判据** 保持原状，本图**不收口**：界外已排除「新增可注入错误接缝」，只观测不注入覆盖不到带状态变化的错误路径。规格留此指针，避免后来者误以为漂移观测已经补上了这个洞。
